AgentOps 项目报告

一个面向 SRE 的只读、证据驱动、可评测的故障初诊 Agent。输入一条告警，它通过六个只读工具查指标、日志、变更、依赖与连接池，在假设看板上维护竞争假设，每条结论都必须引用本次运行中真实产生的证据键，最后输出 FAULT / NOT_A_FAULT / UNKNOWN 三类结构化诊断。

§2问题定义

什么样的故障诊断才算合格

Agent 查几条日志后输出一段通顺的“可能是连接池问题，建议扩容”，在 Demo 里看着像回事，值班工程师却没法接手。项目把这件事拆成四个可以被测量的问题，每个问题对应一处具体的工程设计。

它查了哪些服务、哪个时间窗？
每一步工具调用都写入 EvidenceLedger，通过 SSE 流式推送，并可用 inspect CLI 逐步回看。
结论里的每句话能回到真实证据吗？
报告只能引用本次 Run 产生的 evidence_key；零工具权限的 ReadOnlyVerifier 在采纳前逐条校验。
有没有排除“红鲱鱼”？
场景集专门放入 CPU、磁盘等次要指标越界的干扰题，Verifier 要求跨工具交叉印证并检测矛盾信号。
历史记忆与实时证据冲突时信谁？
记忆只能作为调查线索，不能作为证据键；被实时证据证伪的假设必须标记为 REJECTED。

§6复盘

79/87 失败的那次实测

离线满分，线上几乎全挂

症状 · 10-298 / 87

M4 在真实 deepseek-flash 上只完成 8 次运行，同批次 M3 完成 84 次。

根因Schema 缺失

DiagnosisReport 使用 extra="forbid"，提示词却没注入工具参数和报告字段的 Schema。真实模型自己发明了顶层 evidence_keys，触发校验失败；Fake LLM 硬编码了合法字段，把问题掩盖了。

修复 · 10-3087 / 87

把公共工具目录与报告契约 Schema 注入调查提示词并启用 JSON Mode，不泄露任何场景提示。非法引用采纳率保持 0。

这次故障说明离线 Cassette 门禁和真实模型测量各管一段：前者保证每个 PR 的编排与解析不退化，后者才能暴露“模型不知道输出契约”这类问题。

§8局限与风险

目前还不能下的结论

HIGH
记忆抗污染尚未被证明

M6 真实模型归档中两个启用记忆的组对污染/陈旧记忆的显式拒斥率都是 0/4。离线 Harness 同一指标是 1.0，说明拒斥逻辑在脚本化模型下能跑通，但真实模型没有产生评测器要求的显式拒绝事件。预测结果正确，不能据此宣称记忆能抵抗污染。

HIGH
离线 1.0000 不代表模型能力

M4/M7 的离线满分来自脚本化 Fake LLM。真实模型下无记忆 M4 的 Top-1 为 0.7333，仍低于 M3 的 0.8500。

MED
M6 样本量小

m6-v1 只有 6 个场景，除 agreement@3 外的指标都只统计每组首轮的 6 条记录，不能按 18 次运行解读，也不能与 29 场景的 frozen-v1 直接相减。

MED
夜间真实模型评测处于跳过状态

最近的 nightly-eval 定时运行（11-10 至 11-17）都显示 skipped，工作流在 EVAL_NIGHTLY_ENABLED 未开启时不执行。最后一份真实模型归档停在 11-04。

LOW
数据源仍是模拟器，执行器为单进程

工具读的是 YAML 场景模拟器，不是真实遥测；异步执行在单个进程内完成，不含 Redis 或多副本。两者都在需求文档中被明确列为当前范围，M8 会接入真实观测源。
